# QuizHub — вход игроков: release checklist

## Что реализовано

Экран входа в `app/modules/auth/auth.js` поддерживает:

- существующую регистрацию и вход с email + паролем;
- Google Popup через Firebase Web SDK;
- сброс пароля по email;
- локализованные сообщения об ошибках без системного `alert`;
- постоянную локальную сессию Firebase на одном устройстве.

`app/app.js` продолжает использовать `onAuthStateChanged`, `users/{uid}` и текущие профили.
**Не переносите игроков в новые UID**: смена UID отделит игрока от его сохранённых данных.
Автоматическая привязка Google к существующему email-аккаунту намеренно не добавлена.

## Автоматические проверки

В GitHub Actions `Firebase emulator integration` добавлен тест `tests/firebase-auth-emulator.test.mjs` (прогон #32, 2026-11-15): регистрация тестового email-пользователя, повторный вход с неизменным UID, проверка ID token, неверного пароля, повторной регистрации и выпуска кода восстановления пароля **только внутри Auth Emulator**. Отправка реальных писем, Google Popup и взаимодействие с опубликованной страницей этим тестом не проверяются.

## Браузерная интеграция

В GitHub Actions добавлен `tests/firebase-browser-auth.test.mjs` с Playwright/Chromium. Прогон **Firebase emulator integration #54** (2026-11-15) успешно выполнил в браузере регистрацию по email, сохранение сеанса после перезагрузки, выход и повторный вход с тем же UID. Вызовы направлены на **локальный проект `demo-quizhub`**: код включает его только при `localhost` / `127.0.0.1` и явном параметре `?firebaseEmulator=1`. Google OAuth Popup, настоящие письма и опубликованный сайт пока требуют ручного теста.

## Перед выпуском

1. В [Firebase Authentication](https://console.firebase.google.com/project/quizhub-e65f5/authentication/providers) проверить, включены ли **Email/Password** и **Google**. При необходимости включить в консоли; не менять настройки остальных приложений.
2. В **Authentication → Settings → Authorized domains** проверить точные домены сайта, включая `doctorstrangesh.github.io` и используемый локальный домен для тестов. Не указывать протокол и порт.
3. Проверить вручную в браузере вход существующего email-пользователя, регистрацию нового тестового пользователя, Google-вход, восстановление пароля, выход, перезапуск вкладки, смену устройства и наличие прежнего профиля.
4. Для адреса, который уже привязан к другому способу входа, показать пользователю сообщение об этом; **не создавать автоматически новый аккаунт и не перезаписывать профиль**.
5. Не добавлять приватные ключи или Firebase Admin SDK в браузер.

Код email/password и Google Popup находится в `main`. Настройки Firebase Auth в рабочем проекте из репозитория не читаются и не менялись этим документом. Поэтому проверка реальных Google OAuth, authorized domains и писем остаётся release gate.
